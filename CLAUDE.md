# spiteware.ai — working rules

- **Never commit or push unless the user explicitly says so in that message.** Editing files is fine. Staging, committing, and pushing wait for the word. A push publishes to GitHub Pages at https://spiteware.ai. The one standing exception is the default `/spite` morning run, which commits and pushes its own files (see its skill); nothing else rides along.
- Never use `pkill` in this repo's shell. It kills the session. Check a port with curl and start servers with `(nohup ... &)`.
- The site is static: `index.html` (home, top 6 by spite score), `apps.html` (full catalog with search, tag filter, sort), shared `style.css` and `site.js`, all rendering from `data/apps.json`. No build step, no dependencies. The one external request on every page is Google Analytics (`G-XSP99C36LS`; `submit.html` and `contact.html` alone also load Cloudflare Turnstile): the gtag snippet opens every `<head>`, by hand in `index.html`, `apps.html`, `about.html`, `manifesto.html`, `rules.html`, `submit.html`, `contact.html` and `privacy.html`, and as `GTAG` in `pages.py` for the generated pages.
- `analytics.html` (noindex, not in the sitemap or the nav) shows the site's GA4 numbers. It fetches from `https://stats.spiteware.ai`, the Cloudflare Worker in `workers/analytics-proxy/` (`http://localhost:8788` when previewed locally). The worker holds the Google service account secrets and is deployed by hand with `npx wrangler deploy`, never by a push; setup is in `README.md`. **Never deploy it unless the user says so in that message.** The JSON it returns and the page's `render()` are a pair: change one, change the other.
- There are two forms: `submit.html` (one link box) and `contact.html` (sender email, subject, message: fixes to a card, deletions, feedback, anything else). Both post JSON to `https://submit.spiteware.ai`, the Cloudflare Worker in `workers/submit/` (`http://localhost:8789` locally, with Turnstile's test keys and no email sent), which guards them (Origin, rate limit, honeypot, fill timer, Turnstile) and sends one plain-text email to `MAIL_TO` (hello@spiteware.ai, set in `wrangler.toml`) through Resend. It stores nothing, and `privacy.html` section 04 says so: keep that true. Deployed by hand like the analytics worker, and **never unless the user says so in that message.** The JSON each form posts (`url`; or `kind: "contact"` with `email`, `subject`, `body`) and what the worker reads are a pair: change one, change the other. The address itself is published nowhere but the contact page's send-failure message and the footer of every page links `/contact.html` instead: keep it that way.
- `hall-of-fame/<author>/<app>/`, `404.html`, `sitemap.xml` and `robots.txt` are generated by `python3 scripts/pages.py` and committed. Never edit them by hand. `scripts/merge.py` reruns it on approve; rerun it yourself after hand-editing `data/apps.json` or changing the template. `SW.card`, `SW.victim`, `SW.gh` and `SW.fame` in `site.js` are mirrored in `pages.py`: change one, change the other.
- **No 404s.** `python3 scripts/links.py` checks every internal link offline; `pages.py` runs it after each build and fails on a miss. `--external` checks every outbound URL (GitHub and HN through their APIs) and is part of the `/spite` morning run. Report what it finds DEAD; SUSPECT and UNKNOWN are not findings.
- **Never delete an app from `data/apps.json`, and never rename a `slug` or `builder.handle`:** both are the page's address, and someone has shared it. An app that got taken down is buried instead, on the user's word: `python3 scripts/links.py --bury <slug>` writes `dead_links` (field → Wayback snapshot or `""`) and, when the app's own `url` is gone, `"status": "dead"`. Dead apps drop off the home page, catalog, hall index, counts and sitemap (`site.js` and `pages.py` both filter on `status`), and keep a stamped, noindex hall of fame page.
- Root-relative paths (`/style.css`, `/data/apps.json`) are fine and required for the nested pages: the site is served from the domain root.
- Content is found, checked and scored by an agent, not hand-curated; never describe it as hand-curated or hand-picked. The `/spite` skill drafts candidates into `queue/` and, on the user's standing approval, lists that day's file itself: `python3 scripts/merge.py --approve-all queue/YYYY-MM-DD.json`, then renders the day's short, commits and pushes the run's own files, and uploads the short to YouTube publicly once its hall of fame pages are live. `/spite review` stops at the review desk instead. Outside that run, only the review desk or the user's explicit approval moves a candidate into `data/apps.json`, and the push that publishes it still waits for the user's word.
- **The daily short.** `python3 scripts/short.py` renders `shorts/YYYY-MM-DD.json` (a narration script, committed) into `shorts/YYYY-MM-DD.mp4` (gitignored): `scripts/short.html` screenshotted per caption by headless Firefox, voiced by `scripts/voice.py` through OpenRouter (`OPENROUTER_API_KEY` in `.env`, never committed), cut together by ffmpeg. Every render ends with `scripts/handoff.py` writing the posting desk, `shorts/YYYY-MM-DD.html` (gitignored): the video and each platform's text behind Copy buttons, for the user to post by hand. Format and writing rules are in `shorts/README.md`; `/spite short` writes and renders one after a merge. The frame template links `/style.css` and `short.py` imports `gh()` and `out()` from `pages.py`, so the video follows the site. `python3 scripts/upload.py` puts the mp4 on YouTube through the Data API with the desk's title and description (private by default; `--public`, `--unlisted`, `--at`, `--dry`; `YOUTUBE_*` credentials in `.env`, setup in `shorts/README.md`). **Never upload or post a video unless the user says so in that message**, except the default `/spite` run's one public YouTube upload of the day's short. TikTok and Instagram stay by hand.
- Local preview: `python3 -m http.server 4321` and open http://localhost:4321/. Review desk: `python3 scripts/review.py 4322`.
- Design is locked: flat, thick black borders, hard offset shadows, cream paper, acid yellow, hot pink. Strikethrough "replaces X · $N/mo" badge is the signature element.
